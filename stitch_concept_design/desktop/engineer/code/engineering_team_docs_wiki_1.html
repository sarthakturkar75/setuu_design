Core API Standards & Integration Protocols

Defines the immutable architectural constraints and RESTful design patterns required for all Setuu Enterprise microservices operating within the primary infrastructure cluster.

verified SOC2 Tier 3

All newly provisioned endpoints must adhere strictly to the guidelines defined in this document. Deviation requires explicit approval via the Architectural Review Board (ARB) ticketing system.

1. Authentication Payload Structure

Requests must include a Bearer token in the `Authorization` header. The JWT structure expects standard claims alongside custom tenant identifiers.

json 
{
  "alg": "RS256",
  "typ": "JWT"
}
.
{
  "sub": "usr_9f8a7b6c",
  "tenant_id": "tnt_enterprise_01",
  "role": "admin",
  "exp": 1698420000
}

2. Standard Response Envelopes

To ensure predictability for consuming clients, all API responses (success and error) must be wrapped in a standard envelope. Raw arrays should never be returned at the root level.

Field Type Description Required
data Object|Array The primary resource payload. Null on errors. Yes
meta Object Pagination details, server timestamps, etc. Optional
error Object Error code and human-readable message. Null on success. Cond.
info
Versioning Requirement

API versioning is strictly managed via URI path routing (e.g., `/api/v2/resources`). Header-based versioning is deprecated for internal microservices.
